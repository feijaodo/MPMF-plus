# p8 — raw-message layer (RESEARCH, flag `raw_layer`, default OFF)

## What it is
- `src/mpmf_plus/raw_layer.py`: every real user message becomes a node in its own namespace
  (`_ns = "raw"`, name `rawmsg_<sha1[:20]>`, verbatim text, `embed_text` vector, `_said_at`,
  `_conv_id`, `_msg_index`; no `entity`, so history never sees it). Facts are untouched.
- Nodes in `raw` can never enter default recall (it asks for `("memory",)`).
- Fusion: `hermes_adapter.prefetch` appends a SEPARATE section `# Raw messages you wrote
  (verbatim; ...)` after the facts block: cosine over raw rows only (floor `raw_min_cos`,
  top 20) -> cross-encoder (700 chars, same timeout rule as d20) -> top `raw_k`. Facts bytes are not
  changed, and the raw section can neither displace facts nor be cut by their cap.
- Live write: `sync_turn` stores the user message (flag on only). Backfill:
  `raw_layer.backfill()` (one write txn; refuses the live store without `allow_live`).
- Privacy: secrets, e-mails, phone numbers, host "[System ..." text are never stored.
- Flag off: `prefetch`/`sync_turn` do not touch the module (test_raw_layer.py pins this).

## Config (recall.config.json / `MPMF_<KEY>`)
raw_layer false, raw_k 3, raw_min_cos 0.5, raw_rerank true, raw_item_chars 500, raw_block_chars 1500.

## Results (348 questions: r85b 250 + p6 TUNE 98; LOCKED/HOLDOUT untouched)
Stores: copy of live athena (base, flag off) vs copy + 16,678 raw nodes (full). Scorecard answer/judges unchanged.
- accuracy off 0.4813 -> on 0.6466 (+16.5 pts); strict correct 143 -> 198; gained 65, lost 10; McNemar exact p=5.2e-11
  (correct-or-partly: 68 vs 8). r85b 0.510->0.650 (p<1e-6); TUNE 0.408->0.638 (25 vs 2).
- by type: history +16.3, now +15.0, then +16.9, recent +32.1, order +2.7 (n.s.).
- latency prefetch p50 475 -> 986 ms, p90 550 -> 1436, max 1149 -> 2284 (idle CPU, single-flight). 0 rerank timeouts, 0 errors.
- block size mean 2169 -> 2932 chars. Cost per arm ~$0.20.
- Control: flag off on augmented store gives block bytes identical to base store in 323/348 (25 differ; ranking on store
  with extra rows / non-determinism, not the raw section - none contain the raw header).
- CAVEAT (leakage): questions were generated FROM these same raw user messages, so the raw layer can retrieve the exact source.
  Source message present in on-block for 205/348. Split: src in block: 0.615->0.827 (49 vs 7); src NOT in block: 0.290->0.388 (16 vs 3, p=0.004).
  Treat +16.5 as an upper bound for real-life questions; the TUNE/r85b sets cannot show the real-world rate. LOCKED not used.
- The first off run was taken while corpus embedding loaded the CPU (p50 4127 ms) - discarded; off2 is the reported arm (same accuracy 0.4813).
Flag left OFF (default False, not in live recall.config.json), not deployed.
