# p12 — typed-link walk (RESEARCH, flag `typed_walk`, default OFF)

Code: src/mpmf_plus/typed_walk.py; hook at the end of `_recall_d20` in provider.py (module not imported when flag off).
After d20 builds its final list: take the top `typed_walk_seeds` (4) hits, follow IS_A / DERIVED_FROM / supersedes edges
(either direction, ONE hop), rank neighbours by cosine to the query, the best `typed_walk_k` (2) with cosine >=
`typed_walk_min_cos` (0.3) take the LAST slots (list length unchanged; seeds never evicted; superseded-marked and
non-requested-namespace nodes never injected). Any failure returns the list untouched. Tests: tests/test_typed_walk.py (8).

Store facts (COPY of live athena, 24,662 nodes): DERIVED_FROM 4,615 (state->fact, all memory ns), supersedes 3,793 (only 1,413
memory<->memory; rest ruminate/transcript), IS_A 1,039 (state->category hub, 11 hubs, no fact pair - the walk reaches
the hub only if its text is similar to the query).

Questions (outside repo, private, /root/p12/sets): steps/p12_qgen.py. 160 sampled linked pairs (90 DERIVED_FROM, 70 supersedes),
writer (deepseek-v4.1-flash) sees only the two texts and writes a question needing both; 100 kept. MAIN = 40 where plain
cosine top-8 does NOT contain both source facts (20 per link type). CONTROL = 20 where cosine already has both.
Scoring = scorecard's own answer/judge prompts, 3 judges, majority (unchanged). steps/p12_eval.py, p12_analyze.py.

Result (same store copy, only the flag differs):
- MAIN n=40: strict correct 11 -> 14 (gained 3, lost 0), McNemar exact p=0.25; correct-or-partly gained 2 lost 2, p=1.0; acc 0.400 -> 0.4375.
  DERIVED_FROM (20): 9 -> 9. supersedes (20): 2 -> 5 (p=0.25).
- Retrieval (both source facts in the block): MAIN 12 -> 20 (gained 10, lost 2, McNemar p=0.039); CONTROL 19 -> 19.
- CONTROL n=20: strict 11 -> 13 (p=0.5): no harm seen.
- Latency (prefetch, 60 q): first call p50 582.5 -> 579.3 ms, p90 684.9 -> 677.7; warm (2 repeats) p50 581.0 -> 579.5; walk itself 0.4 ms mean.
  The adjacency index over ~49k edges is built once per store load.
Verdict: the walk puts both facts in the block more often (significant on retrieval) but the answer gain is not significant
at n=40 (3-0). Left OFF. Not deployed, not in auto-revert. p16 (prune tag-overlap edges) is therefore not unlocked.
Caveat: the questions are LLM-written from the edge pairs themselves, and DERIVED_FROM states often restate their facts.
