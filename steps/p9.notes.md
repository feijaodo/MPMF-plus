# p9 — keep details in extraction (flag `keep_details`, default OFF)

## What it is
- `src/mpmf_plus/keep_details.py`: after the per-turn extraction, every fact that is the SOLE fact of its
  evidence sentence is checked: each proper noun, number and date of the evidence must appear in the fact
  sentence (or in `fact_date`). If any fact drops one, the extractor is re-asked ONCE with the dropped items
  named. A retried fact replaces the original only if it is the same fact (same evidence, word overlap >= 0.4),
  has strictly fewer drops and is not a merged/copy-pasted message. Facts are never added or removed.
  A failed retry keeps the originals. `ingest(keep_details=None)` reads config `keep_details` (MPMF_KEEP_DETAILS).
- Off: ingest makes the same single call as before (tests/test_keep_details.py pins this). store.log gets
  `kd_bad= kd_fixed=` only on retried turns.
- Tests: tests/test_keep_details.py (11). deploy gate OK, not deployed.

## Evaluation (steps/p9_eval.py, p9_analyze.py; rows in /root/p9, private, outside the repo)
Real user messages from the p8 corpus. First extraction is shared by both arms, so the only difference is the retry.
Judges: the 3 scorecard judges, blind, specificity 1-5 + number of unsupported facts. Two sample kinds:
random (any 80-600 char message) and dense (>=4 specifics).
- run 1/2 (first design: any fact held to all evidence specifics, best-of retry): specificity -0.02 / -0.10:
  the retry MERGED sibling facts (facts 25->22 on 20 turns) and copied whole messages. Not shippable.
- run 3 (same design, 40 turns): -0.096, 15/40 turns changed, changed-turn specificity -0.26.
- Redesign (sole-fact audit only, sibling-overlap match, no-merge prompt). Final code, two fresh samples:
  run 4 (seed 911) 40 turns: spec 4.017 -> 4.033, unsupported 0.042 -> 0.033, facts 91 -> 91, 2 turns changed.
  run 5 (seed 4242) 40 turns: spec 3.983 -> 3.983, unsupported 0.062 -> 0.062, facts 86 -> 86, 4 turns changed.
  run 4+5 pooled, 80 turns: spec 4.000 -> 4.008 (+0.008), turns up 2 / down 1 / same 77; unsupported -0.004;
  changed turns (6): 4.72 -> 4.83. Retry fired on 14/80 turns, fixed 11 facts on 6 turns.
- Programmatic dropped-specifics count barely moves (518->514, 503->495): the audit's "dropped" counts are dominated
  by multi-fact messages where the specifics are split between facts, which is deliberately not retried.

## Verdict
No drop in correctness, specificity unchanged-to-slightly-up, but the effect is small (6/80 turns changed; sign test not
significant) and it costs one extra extraction call on ~17% of turns. Flag stays OFF; not deployed; not covered by
auto-revert. Enable with `"keep_details": true` after deploy only if Dee wants the small gain for the extra calls.
