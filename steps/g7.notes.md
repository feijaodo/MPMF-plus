# g7 — lessons OFF vs ON-live vs ON-matched on 120 real-incident tasks

Numbers only. Tasks, lesson text, transcripts and session ids stay outside the repo (/root/g7/).

## Design (written to the evidence file before the first model call)
- Model deepseek/deepseek-v4.1-flash in every arm, temperature 0 (harness), max_tokens 1500, max 60 model calls per
  task, one trial per task per arm, 5 worker threads per arm, per-run timeout 900 s, shared spend meter with a
  $10.40 ceiling (a call refused by the ceiling would make the task "not run"; it never triggered).
- Task set: 120 tasks, frozen (chmod 444) before any arm, md5 bf6b6b523a5a06ec8ca981fb9e0796f4. No filtering by
  baseline outcome. 120 distinct source lessons, 63 distinct source sessions. 38 are the p11b frozen tasks (flagged,
  subset analysis below); 82 are new: 27 left over from the 65 p10b candidates, 55 built from lessons staged after
  the p10b export, from the same source-session DB. All 120 passed the scripted-transcript scorer sanity check
  (a correct run passes, a run repeating the incident fails). 120 was reachable, no synthetic padding.
- ON-live: lessons from provider.recall_cognition (cosine champion, top_k 3, min_cos 0.65, vet on, pool size 1575),
  asked once per task prompt on a COPY of the store taken after g1 (md5 equal to the live store at copy time),
  rendered as the live adapter renders them, shown at the model's first completion claim. The task's own lesson was
  not specially included.
- ON-matched: the task's own stored lesson text at the first completion claim (upper bound, as p11b).
- OFF: flag off, no hook, no lesson.
- Flag lessons_at_action stays OFF (default unchanged).

## Hook-fired check
- OFF: 0 of 120 transcripts have a lesson event or a fired hook.
- ON-matched: fired 120 of 120, text in the transcript equal to the task's stored lesson 120/120. At model call
  median 13 (2 to 54). The 3 no-final tasks fired and then ran out of calls after the lesson.
- ON-live: fired 106 of 120; text equal to the recorded retrieved block 106/106. Median call 10 (2 to 40).
  `no lesson retrieved`: 13 tasks (12 below min_cos, 1 filtered by vet), counted and reported, not dropped; they
  show the same behaviour as OFF. 1 task made no completion claim (no event, not an invalid run). 0 invalid runs
  (no task made a claim without the hook firing).
- ON-live retrieval: 120 prompts, 13 empty, mean 2.24 lessons shown, 204 distinct lessons shown, pool size 1575.
  The task's own lesson (or the pool lesson it was merged into) was among those shown for 5 of 120 tasks
  (leakage check: negligible; those 5 passed 3 OFF, 4 ON-live).

## Exact McNemar (b = base fail and arm pass, c = base pass and arm fail)
| comparison | b | c | both pass | both fail | p |
| ON-live vs OFF | 11 | 10 | 57 | 42 | 1.0 |
| ON-matched vs OFF | 17 | 16 | 51 | 36 | 1.0 |
| ON-matched vs ON-live | 14 | 14 | 54 | 38 | 1.0 |
Excluding tasks where either arm had no final message: live vs off b=9 c=10 p=1.0 (n=116); matched vs off b=14
c=15 p=1.0 (n=114). Excluding errors/timeouts: unchanged (there were none).
Subsets, live vs off: p11b-frozen 38 tasks: OFF 11, live 14, matched 16; b=7 c=4 p=0.549 (matched vs off b=10 c=5
p=0.302). New 82 tasks: OFF 56, live 54, matched 52; b=4 c=6 p=0.754 (matched vs off b=7 c=11 p=0.481).
By family (pass counts OFF/live/matched): claim 81 tasks 41/41/41; numbered 39 tasks 26/27/27.

## Effect
EFFECT = no_effect. The rule (ON-live vs OFF p < 0.05 and b > c) is not met: b=11, c=10, p=1.0. Even the
upper-bound arm (ON-matched) does not differ from OFF. The 38-task p11b result (OFF 12 to ON 17) did not repeat
on the same tasks here (11/14/16, p 0.30 to 0.55) and the 82 new tasks went the other way (56/54/52). Flag stays OFF.
